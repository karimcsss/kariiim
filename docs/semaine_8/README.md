### 1. Compilation du dossier final

#### Structure du dossier


#### Contenu de chaque section

**Page de garde** :
- Titre du projet
- Logo établissement (si applicable)
- Noms des membres du groupe
- Formation et niveau (L2)
- Encadrant pédagogique
- Date de remise

**Table des matières** :
- Liste des sections avec numérotation
- Liste des figures/diagrammes
- Liste des tableaux

**1. Cahier des charges** (Semaine 1) :
- Contexte et problématique
- Objectifs du système
- Périmètre
- Acteurs identifiés
- Glossaire métier

**2. Analyse fonctionnelle** (Semaines 2-3) :
- Besoins fonctionnels (BF)
- Besoins non fonctionnels (BNF)
- Matrice de priorisation

**3. Diagrammes des cas d'utilisation** (Semaine 3) :
- Diagramme global
- Diagrammes par acteur
- Descriptions textuelles

**4. Diagrammes de séquence** (Semaines 4-5) :
- Scénarios sélectionnés
- Diagrammes commentés
- Explications des choix

**5. Diagramme de classes** (Semaines 6-7) :
- Dictionnaire des classes
- Diagramme complet
- Descriptions des relations

**6. Glossaire** :
- Tous les termes métier
- Acronymes
- Conventions de nommage

**7. Annexes** (optionnel) :
- Références bibliographiques
- Entretiens/interviews
- Prototypes d'interfaces
- Données de test

### 2. Vérification de la cohérence

#### Checklist de cohérence globale

**Entre cahier des charges et analyse fonctionnelle** :
- [ ] Tous les objectifs ont des BF correspondants
- [ ] Tous les acteurs identifiés ont des cas d'utilisation
- [ ] Le vocabulaire est cohérent

**Entre analyse fonctionnelle et cas d'utilisation** :
- [ ] Chaque BF majeur a un cas d'utilisation
- [ ] Les acteurs sont les mêmes
- [ ] Les priorités sont cohérentes

**Entre cas d'utilisation et diagrammes de séquence** :
- [ ] Les cas d'utilisation sélectionnés sont justifiés
- [ ] Les acteurs dans les séquences correspondent aux UC
- [ ] Les scénarios reflètent les descriptions des UC

**Entre diagrammes de séquence et diagramme de classes** :
- [ ] Les participants "Entity" sont devenus des classes
- [ ] Les relations dans les séquences se retrouvent dans les classes
- [ ] Les méthodes clés sont présentes

**Cohérence générale** :
- [ ] La terminologie est uniforme dans tous les documents
- [ ] Les numérotations sont cohérentes (BF-XX, UC-XX, etc.)
- [ ] Les références croisées sont correctes
- [ ] Le style et le format sont homogènes

### 3. Préparation de la présentation orale

#### Structure de la présentation (15-20 minutes)

**1. Introduction (2 min)**
- Présentation de l'équipe
- Contexte du projet
- Problématique

**2. Cahier des charges (2-3 min)**
- Objectifs du système
- Acteurs principaux
- Périmètre (inclus/exclus)

**3. Analyse fonctionnelle (3-4 min)**
- Besoins fonctionnels clés (top 5)
- Besoins non fonctionnels critiques
- Diagramme de cas d'utilisation global

**4. Analyse détaillée (4-5 min)**
- Présentation d'1-2 diagrammes de séquence
- Explication des interactions clés
- Choix de conception importants

**5. Modélisation statique (4-5 min)**
- Présentation du diagramme de classes
- Classes principales et leurs relations
- Points techniques intéressants

**6. Conclusion (2 min)**
- Bilan du projet
- Difficultés rencontrées et solutions
- Perspectives d'évolution

**7. Questions/Réponses (5-10 min)**
- Être prêt à justifier tous les choix
- Être prêt à expliquer n'importe quel diagramme

#### Support de présentation

**Slides recommandés** :
- 1 slide de titre
- 1 slide d'introduction/contexte
- 1 slide sur les acteurs
- 1 slide de diagramme de cas d'utilisation
- 2-3 slides de diagrammes de séquence
- 2 slides de diagramme de classes
- 1 slide de conclusion

**Conseils pour les slides** :
- Visuels clairs et lisibles
- Pas trop de texte
- Diagrammes bien dimensionnés
- Animations sobres
- Numérotation des slides

#### Conseils pour l'oral

**Préparation** :
- Répéter plusieurs fois (chronométrer)
- Répartir la parole équitablement
- Prévoir des transitions fluides
- Anticiper les questions probables

**Pendant la présentation** :
- Parler clairement et à un rythme adapté
- Regarder l'audience, pas les slides
- Utiliser un pointeur laser si nécessaire
- Gérer le temps (ne pas déborder)

**Pour les questions** :
- Écouter la question jusqu'au bout
- Reformuler si nécessaire
- Répondre clairement
- Admettre si on ne sait pas
- Se répartir les questions dans l'équipe

## 💡 Conseils de dernière minute

### Erreurs fréquentes à éviter

❌ **À éviter** :
- Présenter sans avoir répété
- Lire les slides pendant la présentation
- Déborder du temps imparti
- Monopoliser la parole
- Paniquer face aux questions
- Oublier de conclure

✅ **À faire** :
- Préparer des réponses aux questions probables
- Avoir des exemples concrets prêts
- Montrer l'enthousiasme pour le projet
- Être honnête si on ne sait pas
- Remercier le jury

### Questions probables

Préparez vos réponses pour :
1. "Pourquoi avez-vous fait ce choix de modélisation ?"
2. "Comment gérez-vous [cas particulier] ?"
3. "Quelle est la différence entre [concept A] et [concept B] ?"
4. "Que feriez-vous différemment si c'était à refaire ?"
5. "Comment ce système s'intégrerait dans l'environnement existant ?"
